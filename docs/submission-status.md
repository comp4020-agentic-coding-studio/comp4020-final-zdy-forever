## 文献阅读入口

以下是阅读提示，不代表你已经阅读或同意。此次 agent 核对了三篇研究的摘要与两篇实践文章；没有据此声称完整审读研究论文。要在提交中进一步讨论方法，请读论文相关部分。

1. [Willison：Writing code is cheap now](https://simonwillison.net/guides/agentic-engineering-patterns/code-is-cheap/)（实践观点）：生成代码变便宜，但确认软件有用、正确且可维护仍有成本。与你的观点衔接处是“验收工作也可以委托到什么程度”。
2. [Böckeler：Harness engineering for coding agent users](https://martinfowler.com/articles/harness-engineering.html)（实践框架）：用前置指引与执行后的检查约束 agent，区分确定性的工具检查和模型判断。思考你愿意亲自保留哪些验收决定。
3. [Vella 与 Blincoe，2026](https://arxiv.org/abs/2605.23135)（纵向研究预印本）：工作重心转向指挥、评估和纠正；自报生产力提升不等于体验改善。问卷结果不能证明“不需要技术理解”。
4. [Cihan 等，2025](https://arxiv.org/abs/2505.20206)（代码审查研究预印本）：模型能帮助审查，但仍会错；提供问题描述会影响表现。有限代码基准不能直接代表整个生产系统或所有新模型。
5. [Balepur 等，2026](https://arxiv.org/abs/2607.26375)（进行中的研究预印本）：54 名学生使用 agent 完成初始任务更容易，但理解及无 agent 扩展表现受到影响。这是对你的立场的重要反例；无辅助任务的结果也不能直接证明持续使用 agent 时必须掌握全部细节。

README 新增的 [Sloan：An app can be a home-cooked meal](https://www.robinsloan.com/notes/home-cooked-app/)用来阐释小群体软件的价值。它是在本次整理时引入的比较，不是你开发前已读过的灵感来源。
